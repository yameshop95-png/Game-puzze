## 1. Phạm vi

**Trong phạm vi (S1-01):** một file duy nhất
`lib/services/asset_loader.dart` chứa cả hai khai báo
(quyết định SA-4):

- `PuzzleAsset` — model bất biến của một hình đã nạp.
- `AssetLoader` — đọc chuỗi JSON manifest qua hàm đọc được
  tiêm vào, giải mã, kiểm cấu trúc, trả `List<PuzzleAsset>`.

**Ngoài phạm vi:**

- Hình duyệt thật: **chưa có hình nào được duyệt**
  (`content/` chưa tồn tại trong repo). S1-01 dùng manifest
  giả trong `test/fixtures/` theo đúng chữ MUSE_STEPS —
  không tạo `content/`, không đưa ảnh/manifest giả vào
  `content/`.
- Validator Python nới để nhận danh sách (hệ quả của SA-1):
  **việc pipeline riêng**, ghi ở §8 — không làm trong chồng
  S1-01 này, không chặn test loader.
- Sửa schema pipeline theo định dạng image_id mới (hệ quả
  của SA-2): cũng là việc pipeline riêng, xem §8.
- `en_alt` (đáp án phụ cho ghép chữ): **không** thuộc
  S1-01 (quyết định SA-5) — điểm hẹn chính thức chuyển sang
  contract S2-01.
- Nạp file ảnh thật (play.webp/thumb.webp) vào bộ nhớ, giải
  mã ảnh, hiển thị: việc của S1-03/S1-04. Loader chỉ trả
  đường dẫn dạng chuỗi trong model.
- `AssetLoader` nằm ở `lib/services/` — **không** thuộc
  `lib/engine/`, cổng purity của engine không áp cho file

## 2. Quyết định SA-1 — Dạng manifest: một file, một danh sách (Opus chốt theo James)

`content/manifest.json` là **một file duy nhất** chứa **một
mảng JSON ở cấp trên cùng**; mỗi phần tử của mảng là một bản
ghi hình theo dạng ở §4. Khớp cây §1 của MUSE_STEPS và
đường CI hiện tại. Hệ quả validator Python phải nới để nhận
danh sách: xem §8.

## 3. Quyết định SA-2 — Định dạng image_id (Opus chốt theo James)

image_id dạng `<theme>_<level>_<nn>`, ví dụ `animals_1_01`
— theo MUSE_STEPS §3 và engine E6 (`random_picker` nhận
pool là các image_id dạng này). Schema pipeline hiện còn
ghim mẫu cũ `^[a-z]+-[0-9]{3}$`; việc sửa schema thuộc phía
pipeline (§8). **Loader không tự kiểm mẫu image_id** — theo
SA-3, loader chỉ kiểm image_id là chuỗi không rỗng; luật
mẫu định danh là luật của validator.

## 4. Dạng bản ghi JSON (đối chiếu schema gốc trong repo)

Tên khóa lấy **nguyên từ schema gốc**
`content_pipeline/manifest.schema.json` (snake_case), giữ
nguyên kiểu dữ liệu của schema. Một bản ghi trong mảng của
`content/manifest.json` có dạng:

```json
{
  "image_id": "animals_1_01",
  "theme": "animals",
  "level": 1,
  "title": "Red Fox",
  "creator": { "name": "…", "anonymous": false },
  "creation_year": 1845,
  "source": { "institution": "…", "object_url": "…",
              "record_id": "…", "license_text": "…",
              "license_evidence_url": "…",
              "retrieved_on": "…" },
  "rights": { "status": "cc0",
              "contains_identifiable_person": false,
              "trademark_or_logo": false },
  "image": { "file": "…", "sha256": "…",
             "short_side_px": 1200, "phash": "…" },
  "text": { "en": "A red fox sits in the grass." },
  "reviewed_by": "…",
  "reviewed_on": "2026-11-27"
}
```

**Ánh xạ bản ghi → `PuzzleAsset`** (trường model theo SA-4):

| Trường model | Nguồn trong bản ghi | Ghi chú |
|---|---|---|
| `id` | `image_id` | chuỗi, dạng SA-2 |
| `theme` | `theme` | chuỗi |
| `level` | `level` | **số nguyên** — xem điểm lệch ghi rõ bên dưới |
| `title` | `title` | chuỗi |
| `textEn` | `text.en` | chuỗi (SA-5: chỉ một chuỗi `en`) |
| `playPath` | suy ra theo quy ước cây §1 | `packs/<theme>/<level>/<image_id>/play.webp` |
| `thumbPath` | suy ra theo quy ước cây §1 | `packs/<theme>/<level>/<image_id>/thumb.webp` |
| `creator` | `creator.name` | schema gốc: `creator` là object, tên nằm ở `creator.name` |
| `institution` | `source.institution` | schema gốc: institution nằm trong object `source` |

**Hai điểm định nghĩa suy ra từ nguồn (chờ Opus xác nhận
khi soát, không phải chốt SA):**

1. `playPath`/`thumbPath` không phải khóa trong schema gốc
   (schema chỉ có `image.file` là file nguồn của pipeline).
   Cây §1 của MUSE_STEPS chốt quy ước đóng gói
   `content/packs/<theme>/<level>/<image_id>/{play.webp,
   thumb.webp}` — contract định nghĩa hai trường này là
   đường dẫn **tương đối so với thư mục `content/`**, suy ra
   tất định từ (theme, level, image_id) theo quy ước đó.
   Loader không đọc khóa `image` để tạo đường dẫn.
2. `creator`/`institution` trong model là chuỗi phẳng:
   `creator` ← `creator.name`, `institution` ←
   `source.institution`. Các khóa còn lại của hai object đó
   là dữ liệu của validator/credits chi tiết ở S4, loader
   không mang theo.

**Điểm lệch chữ giữa SA-3 và schema gốc (ghi rõ để Opus
xác nhận):** comment `7227884824` viết "theme/level là
chuỗi không rỗng", nhưng schema gốc trong repo định nghĩa
`level` là **số nguyên** (`"type": "integer"`, minimum 1,
maximum 5) — và `level` cũng là số trong chính định dạng
image_id `<theme>_<level>_<nn>`. Contract này theo **schema
gốc**: `level` trong JSON là số nguyên, `PuzzleAsset.level`
là `int`; phần "chuỗi không rỗng" áp cho `theme` (và các
chuỗi có `minLength: 1` trong schema: `title`, `text.en`).
Test UNIT-AL-05 ghim: `level` là chuỗi → `FormatException`.

## 5. Quyết định SA-3 — Mức xác thực + hành vi lỗi (Opus chốt theo James)

Loader **chỉ kiểm cấu trúc trong Dart**; luật bản quyền /
CC0 / public-domain của validator Python **không lặp lại**
trong Dart. Cụ thể, loader kiểm:

1. Cấp trên cùng của JSON phải là một **mảng** — không
   phải mảng → `FormatException`.
2. Mỗi phần tử phải là một **object** JSON — không phải
   object → `FormatException`.
3. Mọi khóa **bắt buộc ở cấp trên cùng theo schema gốc**
   phải có mặt: `image_id`, `theme`, `level`, `title`,
   `creator`, `creation_year`, `source`, `rights`, `image`,
   `text`, `reviewed_by`, `reviewed_on`. Thiếu một khóa →
   `FormatException`.
4. Đúng kiểu theo schema gốc cho các khóa cấp trên cùng:
   chuỗi (`image_id`, `theme`, `title`, `reviewed_by`,
   `reviewed_on`), số nguyên (`level`, `creation_year`),
   object (`creator`, `source`, `rights`, `image`, `text`).
   Sai kiểu → `FormatException`. (`level` dạng số thực như
   `1.5` cũng là sai kiểu: `jsonDecode` cho `double`, không
   phải `int`.)
5. Chuỗi không rỗng ở các trường schema gốc có
   `minLength: 1` hoặc là định danh: `image_id`, `theme`,
   `title`, `text.en`. Rỗng → `FormatException`.
6. Kiểm sâu **chỉ ở các giá trị model tiêu thụ**: `text`
   phải là object chứa `en` là chuỗi không rỗng; `creator`
   phải là object chứa `name` là chuỗi; `source` phải là
   object chứa `institution` là chuỗi. Ngoài ba điểm này,
   nội dung lồng nhau của `creator`/`source`/`rights`/
   `image` là phần của validator Python — loader không
   kiểm sâu.

**Không kiểm (ghi rõ lựa chọn, test ghim theo lựa chọn):**

- **Trường lạ** (khóa không có trong schema): loader **bỏ
  qua**, nạp bình thường. `additionalProperties: false` là
  luật của validator Python, không phải của loader
  (UNIT-AL-10).
- Khoảng giá trị `level` (1..5), mẫu image_id, enum theme,
  định dạng ngày/URI, hash: luật schema/validator, loader
  không lặp lại.

**Hành vi lỗi:** gặp bản ghi hỏng **đầu tiên** theo thứ tự
duyệt mảng → ném `FormatException` **toàn cục**, không trả
danh sách một phần, không nuốt từng bản ghi (nội dung đóng
gói sẵn — lỗi manifest là lỗi build). JSON hỏng cú pháp:
`jsonDecode` tự ném `FormatException` — loader để nguyên
lỗi đó truyền ra (UNIT-AL-09 ghim đúng kỳ vọng này).

## 6. Quyết định SA-4 — API + model (Opus chốt theo James)

```dart
// lib/services/asset_loader.dart
import 'dart:convert';
import 'package:flutter/services.dart' show rootBundle;

/// Một hình đã nạp từ manifest. Bất biến.
class PuzzleAsset {
  final String id;
  final String theme;
  final int level;
  final String title;
  final String textEn;
  final String playPath;
  final String thumbPath;
  final String creator;
  final String institution;

  const PuzzleAsset({
    required this.id,
    required this.theme,
    required this.level,
    required this.title,
    required this.textEn,
    required this.playPath,
    required this.thumbPath,
    required this.creator,
    required this.institution,
  });
}

class AssetLoader {
  /// Đường dẫn manifest mặc định (tương đối so với asset
  /// root của app, khớp cây §1: content/manifest.json).
  static const String manifestPath = 'content/manifest.json';

  /// [loadString] tùy chọn: hàm đọc chuỗi theo đường dẫn,
  /// mặc định là rootBundle.loadString. Test tiêm hàm giả.
  AssetLoader({Future<String> Function(String)? loadString});

  /// Đọc manifest tại [manifestPath], kiểm cấu trúc theo
  /// contract S1-01, trả danh sách theo đúng thứ tự mảng.
  /// Ném FormatException ở bản ghi hỏng đầu tiên.
  Future<List<PuzzleAsset>> load();
}
```

- `load()` không tham số: đường dẫn luôn là
  `AssetLoader.manifestPath` (UNIT-AL-02 ghim hàm đọc giả
  được gọi đúng với đường dẫn này).
- Thứ tự kết quả = thứ tự bản ghi trong mảng (UNIT-AL-01).
- Model bất biến, gồm `creator`/`institution` ngay từ đầu
  để tránh sửa model ở S4 (lý do của Opus).
