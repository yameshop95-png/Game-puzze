## 2. SA-UI-1 — Đơn vị hiển thị + ngữ nghĩa "khóa" (Opus chốt)

5 thẻ chủ đề. Khóa = trạng thái cổng của **cấp tiếp
theo** của chủ đề đó, tính bằng `gate.dart` (luật
75%). Chủ đề bản thân **không bao giờ bị khóa** — thẻ
luôn chọn được, kể cả khi badge khóa đang hiện (ghim
bởi WID-TS-05). Badge khóa là overlay trên thẻ, không
che tên chủ đề. Chọn cấp và gameplay thuộc S1-04 trở
đi.

Suy ra trực tiếp từ chốt + contract E5 (ghi rõ, chờ
Opus xác nhận): trạng thái cổng của một chủ đề tính
trên tổng hợp của chủ đề — `isUnlocked(solvedCount,
puzzleCount, threshold)` với `solvedCount`/`puzzleCount`
theo §5. Hệ quả theo quyết định 3 của E5: chủ đề chưa
có hình nào (`puzzleCount == 0`) thì cổng chưa mở —
badge khóa hiện.

## 5. Cấu trúc view-model / provider (suy ra từ SA-UI-3/4, chờ Opus xác nhận)

File `lib/features/theme_select/theme_progress.dart`:

```dart
/// Một chủ đề trong catalog cố định (SA-UI-2).
class ThemeInfo {
  final String id;
  final String displayName;
  const ThemeInfo(this.id, this.displayName);
}

/// Catalog cố định, đúng thứ tự SA-UI-2.
const List<ThemeInfo> themeCatalog = [
  ThemeInfo('animals', 'Animals'),
  ThemeInfo('landscapes', 'Landscapes'),
  ThemeInfo('space', 'Space'),
  ThemeInfo('maps', 'Maps'),
  ThemeInfo('landmarks', 'Landmarks'),
];

/// Dữ liệu hiển thị của một thẻ chủ đề, đã tính xong.
class ThemeViewModel {
  final String themeId;
  final String displayName;
  final int puzzleCount;   // số hình hiện có của chủ đề
  final int solvedCount;   // số hình của chủ đề đã giải
  final bool nextLevelLocked;
  const ThemeViewModel({...});
}

/// Nguồn dữ liệu cho màn chọn chủ đề (SA-UI-3).
abstract class ThemeProgressProvider {
  Future<List<ThemeViewModel>> loadThemes();
}

/// Kiểu của cổng E5, tiêm được để unit test thay cổng giả.
typedef GateCheck = bool Function(
  int solvedOwned, int totalOwned, double threshold);

/// Tính view-model của một chủ đề (SA-UI-3).
Future<ThemeViewModel> computeThemeViewModel(
  String themeId, {
  required AssetLoader assetLoader,
  required ProgressDao progressDao,
  GateCheck gate = isUnlocked,
  double threshold = 0.75,
});

/// Provider thật: chạy computeThemeViewModel cho cả
/// 5 chủ đề theo thứ tự catalog.
class AssetThemeProgressProvider
    implements ThemeProgressProvider { ... }
```

Luật tính (ghim bởi WID-TS-11..15):

1. `puzzleCount` = số bản ghi manifest có
   `theme == themeId` (qua `AssetLoader.load()`).
2. `solvedCount` = số hình **của chủ đề đó** đã giải
   ở **bất kỳ mode nào** — hợp của
   `ProgressDao.solvedIds('jigsaw')` và
   `solvedIds('word')` giao với id các hình của chủ
   đề. Cơ sở: spec/E5 — giải bằng chế độ nào cũng
   tính; cổng E5 đếm theo (solvedOwned, totalOwned)
   đã tổng hợp ở tầng gọi.
3. `totalOwned = puzzleCount` (SA-UI-3, tới S3).
4. `nextLevelLocked = !gate(solvedCount, totalOwned,
   threshold)`. `threshold` truyền qua tham số, mặc
   định 0.75 — nguồn duy nhất là
   `harness/thresholds.yaml`, `config/game_config.json`
   là bản sao; business logic không tự đọc file config
   (mẫu E5).
5. `themeId` không thuộc catalog → `ArgumentError`
   (suy ra: catalog là nguồn tên hiển thị duy nhất,
   id lạ là lỗi lập trình, nổ sớm thay vì hiện thẻ
   không tên).
