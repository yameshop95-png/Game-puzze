## 3. Quyết định 2 — Ngữ nghĩa normative: requiredSolved là định nghĩa gốc (Opus chốt theo James)

```
requiredSolved(n, t) = (t * n).floor() + 1
isUnlocked(s, n, t)  = s >= requiredSolved(n, t)
```

Trong đó `n` = totalOwned, `t` = threshold, `s` = solvedOwned.

1. `isUnlocked` **định nghĩa qua** `requiredSolved` — không so
   sánh tỉ lệ double ở bất kỳ đâu. Cách đọc này tương đương công
   thức gốc của §E5 ("lớn hơn threshold") và cách đọc đã chốt
   ("số nguyên nhỏ nhất lớn hơn 75% số hình thực tế"): cần giải
   số hình nguyên nhỏ nhất mà tỉ lệ của nó **vượt** threshold.
2. Hệ quả của `floor + 1`: khi `t * n` là số nguyên (ví dụ
   0.75 × 4 = 3) thì cần 4, không phải 3 — đạt đúng 75% là
   **chưa** mở, vì luật là `>` nghiêm ngặt, không phải `>=`.
3. **Test chỉ ghim threshold là phân số nhị phân chính xác:**
   0.75, 0.5, 0.25, 0.125. Không ghim 0.1 / 0.3 / 0.29 — các giá
   trị đó không biểu diễn chính xác được trong số thực dấu phẩy
   động, nên tích `t * n` có sai số làm tròn riêng và hành vi ở
   biên không phải là một phần của contract này. Threshold
   chuẩn của game (0.75) là nhị phân chính xác.

## 4. Quyết định 3 — Ca biên đầu vào (Opus chốt theo James, chốt thêm requiredSolved(0, t) = 1)

| Đầu vào | Hành vi |
|---|---|
| `totalOwned == 0` | `isUnlocked` → `false` (trạng thái hợp lệ, không ném lỗi — chưa sở hữu hình nào thì cổng chưa mở được) |
| `requiredSolved(0, t)` | → `1` (công thức cho `(t * 0).floor() + 1 = 1`, không ném lỗi) |
| `solvedOwned < 0` | `ArgumentError` |
| `totalOwned < 0` | `ArgumentError` (cả hai hàm) |
| `solvedOwned > totalOwned` | `ArgumentError` (chỉ `isUnlocked` mới có `solvedOwned`) |
| `threshold <= 0` hoặc `threshold > 1` hoặc NaN hoặc ±∞ | `ArgumentError` — threshold hợp lệ thuộc khoảng `(0, 1]` |

Hệ quả đã chốt của khoảng `(0, 1]`:

- `threshold == 1` hợp lệ: `requiredSolved(n, 1) = n + 1` — không
  bao giờ mở (đạt 100% vẫn chưa đủ, vì luật là vượt 100%).
- `threshold` rất nhỏ vẫn hợp lệ (ví dụ 0.125): công thức chạy
  như thường.

Validation viết đúng mẫu Opus đã cho trong comment
`7218341139`: kiểm threshold trước (cả hai hàm), sau đó kiểm
`totalOwned`, `solvedOwned` (chỉ `isUnlocked`), rồi mới tới ca
`totalOwned == 0` trả `false`. Thứ tự kiểm này có nghĩa: đầu vào
vừa sai vừa thuộc ca biên thì **lỗi thắng** (ví dụ
`solvedOwned > totalOwned` khi `totalOwned == 0` vẫn ném
`ArgumentError`, không trả `false`).

## 7. API (ghi nguyên signature + mẫu validation của Opus)

```dart
// lib/engine/progress/gate.dart
// Pure Dart, no imports needed.

/// Returns true when the player has solved strictly more than
/// [threshold] of the [totalOwned] puzzles they own.
/// Throws [ArgumentError] for invalid inputs
/// (see [requiredSolved]).
/// Returns false when [totalOwned] == 0 (gate cannot open yet).
bool isUnlocked(int solvedOwned, int totalOwned, double threshold);

/// The minimum number of owned puzzles the player must solve
/// to unlock.
/// Defined as floor(threshold × totalOwned) + 1 — integer
/// arithmetic, no floating-point comparison at the call site.
/// Throws [ArgumentError] for invalid inputs.
/// Returns 1 when [totalOwned] == 0.
int requiredSolved(int totalOwned, double threshold);
```

Validation (đúng mẫu Opus):

```dart
// Cả hai hàm:
if (threshold <= 0 || threshold > 1 ||
    threshold.isNaN || threshold.isInfinite)
  throw ArgumentError.value(
      threshold, 'threshold', 'must be in (0, 1]');

// Chỉ isUnlocked:
if (totalOwned < 0)
  throw ArgumentError.value(totalOwned, 'totalOwned', 'must be >= 0');
if (solvedOwned < 0)
  throw ArgumentError.value(solvedOwned, 'solvedOwned', 'must be >= 0');
if (solvedOwned > totalOwned)
  throw ArgumentError.value(
      solvedOwned, 'solvedOwned', 'must be <= totalOwned');
if (totalOwned == 0) return false;  // valid state, not an error

// Chỉ requiredSolved:
if (totalOwned < 0)
  throw ArgumentError.value(totalOwned, 'totalOwned', 'must be >= 0');
// totalOwned == 0: returns 1, no error
```
