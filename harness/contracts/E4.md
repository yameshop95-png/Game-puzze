## 2. Quyết định 1 — Token = TỪ (Opus chốt, khác khuyến nghị James)

1. `Sentence.parse` tách theo khoảng trắng (mọi dãy `\s+` là một
  dấu tách: khoảng trắng thừa, tab, newline đều gộp). Dấu câu **dính
  vào từ như gốc** — token giữ nguyên văn hoa/thường và dấu câu.
2. **Mảnh chỉ-dấu-câu** (mảnh mà khóa chuẩn hóa rỗng, ví dụ `—`):
  gộp vào token đứng **trước** (text nối thêm bằng một khoảng
  trắng); nếu mảnh đứng đầu câu (chưa có token trước) thì gộp vào
  token đứng **sau**. Mảnh chỉ-dấu-câu không bao giờ thành token
  riêng và không đóng góp khóa nào.
3. Chuỗi rỗng / toàn khoảng trắng → `ArgumentError`. Chuỗi chỉ gồm
  mảnh dấu câu (không token thật nào) → `ArgumentError`.
4. **Lối thoát cụm/câu:** `Sentence.fromTokens(List<String>)` nhận
  token do caller chia sẵn (một token có thể là cụm nhiều từ).
  Danh sách rỗng, token trống/toàn khoảng trắng, hoặc token không
  có khóa nào (chỉ dấu câu) → `ArgumentError`.
5. `Sentence.text` = nối text các token bằng một khoảng trắng —
  với `parse`, đây là dạng đã chuẩn hóa khoảng trắng của câu gốc.

## 3. Quyết định 2 — Đáp án do caller cấp, dạng `List<String>` (Opus chốt (c))

1. `AnswerValidator(Sentence sentence, {List<String> alternates})`:
  câu gốc là **đáp án số 0 ngầm định**; `alternates` là các câu đầy
  đủ do tầng trên (dữ liệu) cấp. Engine không đọc manifest.
2. `answers` (getter): danh sách **không sửa được**, câu gốc đứng
  đầu, đã **khử trùng theo dãy khóa** — alternate nào có dãy khóa
  trùng một đáp án đã có (chỉ khác hoa/thường/dấu câu) thì không
  thêm vào nữa (test ENG-W-22).

## 4. Quyết định 3 — So sánh theo KHÓA CHUẨN HÓA (Opus chốt, khác khuyến nghị James)

1. **Khóa của một từ** = bỏ dấu câu ở **hai đầu**, rồi
  `toLowerCase()`. "Dấu câu ở hai đầu" ghim chính xác là: mọi ký tự
  đầu/cuối **không phải chữ (Unicode letter) cũng không phải số
  (Unicode digit)** đều bị bỏ, lặp lại cho tới khi gặp chữ/số hoặc
  hết chuỗi. Dấu câu **giữa** từ giữ nguyên (`don't`,
  `well-known`). Tập ký tự bị bỏ ở hai đầu được ghim bằng test
  ENG-W-08 (dấu ASCII, ngoặc cong, ngoặc kép cong, guillemet, gạch
  ngang dài/ngắn, …).
2. `Sentence.normalizeWords(String)` (static, public): tách theo
  `\s+`, chuẩn hóa từng từ theo luật 1, **bỏ từ có khóa rỗng**, trả
  danh sách khóa theo thứ tự. `WordToken.keys` =
  `normalizeWords(text)` của token đó (token từ = đúng 1 khóa;
  token cụm của `fromTokens` = nhiều khóa). Dãy khóa của một câu =
  ghép `keys` của các token theo thứ tự.
3. **Thứ tự đúng** = dãy khóa của các token người chơi xếp **bằng**
  dãy khóa của ít nhất một đáp án. So sánh ở cấp **từ** (dãy khóa),
  không so chuỗi thô — nên chip mang dấu câu/hoa khác vị trí vẫn
  khớp đáp án (ENG-W-16, ENG-W-17), và hai chip giống hệt nhau đổi
  chỗ vẫn đúng (ENG-W-18).
4. **Kiểm ngay khi tạo validator:** mọi đáp án (gồm alternate) phải
  có **cùng multiset khóa** với câu gốc; sai → `ArgumentError`
  ngay trong constructor (lỗi dữ liệu nổ ở pipeline/test, không nổ
  lúc người chơi chơi).
5. `check(List<int> order)`:
   - index trùng, âm, hoặc ≥ số token → `ArgumentError`;
   - `order.length < n` (kể cả rỗng) → `WordCheckStatus.incomplete`;
   - `order.length == n` → `correct` (kèm `matchedAnswer` = chuỗi
     đáp án khớp, nguyên văn như đã cấp) hoặc `incorrect`
     (`matchedAnswer` = null).
   `accepts(order)` = `check(order).isCorrect`.
6. **TODO (ghi nhận, không chặn):** `toLowerCase()` chỉ đúng cho
  tiếng Anh — chấp nhận được vì game chỉ có tiếng Anh; nếu sau này
  thêm ngôn ngữ có luật hoa/thường đặc biệt (ví dụ tiếng Thổ) phải
  xem lại luật khóa.

## 5. Quyết định 4 — Xáo: Fisher–Yates, kết quả KHÔNG được là đáp án (Opus chốt, khác khuyến nghị James)

1. `Sentence.shuffle(Random)`: Fisher–Yates trên danh sách chỉ số
  `0..n-1` — duyệt `i` từ `n-1` xuống `1`, `j = random.nextInt(i+1)`,
  hoán đổi. Thuần túy, không xét đáp án, không đổi Sentence. Tất
  định theo seed của `Random` được tiêm vào.
2. `AnswerValidator.scramble(Random, {int maxAttempts = 64})`:
  xáo bằng `Sentence.shuffle` trên **cùng** một `Random`, tối đa
  `maxAttempts` lần, trả lần xáo đầu tiên **không phải đáp án hợp
  lệ**. `maxAttempts < 1` → `ArgumentError`. Không ép derangement
  (hoán vị được phép giữ nguyên vị trí một số token — chỉ cấm
  trùng hẳn một đáp án).
3. **Ca biên không tồn tại thứ tự sai:** nếu mọi hoán vị đều là đáp
  án (1 token; mọi khóa giống nhau; alternate phủ hết hoán vị) thì
  `canScramble == false`. Khi đó `scramble` vẫn xáo đủ
  `maxAttempts` lần và **trả lần xáo cuối, không ném lỗi**.
4. `canScramble` (định nghĩa chính xác): số dãy khóa phân biệt
  dựng được từ các token **lớn hơn** số dãy khóa đáp án phân biệt
  dựng được — tức còn tồn tại ít nhất một thứ tự không phải đáp án.

## 7. API (ghi nguyên signature Opus, kèm luật ghim của James)

```dart
// lib/engine/word/sentence.dart — chỉ import dart:math show Random
final class WordToken {
  const WordToken(this.index, this.text);
  final int index;        // vị trí trong thứ tự gốc, 0..n-1
  final String text;      // nguyên văn: giữ hoa/thường + dấu câu dính
  List<String> get keys;  // khóa chuẩn hóa của token (không sửa được)
}

final class Sentence {
  factory Sentence.parse(String text);              // quyết định 1
  factory Sentence.fromTokens(List<String> tokens);
  String get text;              // nối tokens bằng ' '
  List<WordToken> get tokens;   // không sửa được
  int get length;
  List<int> shuffle(Random random);   // quyết định 5.1
  static List<String> normalizeWords(String s);
}

sealed class WordCommand { const WordCommand(); }
final class PickToken extends WordCommand {   // pool → cuối hàng đáp án
  const PickToken(this.tokenIndex);
  final int tokenIndex;
}
final class ReturnToken extends WordCommand { // hàng đáp án → pool
  const ReturnToken(this.tokenIndex);
  final int tokenIndex;
}

final class WordBoard {
  factory WordBoard.initial(List<int> order);
  List<int> get order;    // thứ tự xáo ban đầu (không sửa được)
  List<int> get answer;   // token đã xếp, theo thứ tự chạm (không sửa được)
  List<int> get pool;     // = order trừ answer, giữ thứ tự tương đối của order
  bool get isFull;        // pool rỗng
  WordBoard apply(WordCommand command);   // bất biến: trả board MỚI
  Map<String, Object> toMap();            // {'v':1,'order':[..],'answer':[..]}
  factory WordBoard.fromMap(Map<String, Object?> map);
}
```

Luật ghim thêm cho `WordBoard` (James chốt theo đúng mẫu E1/E3,
nêu rõ để Opus duyệt):

1. `initial`: danh sách rỗng hoặc không phải hoán vị đúng của
  `0..length-1` (trùng / thiếu / ngoài khoảng) → `ArgumentError`.
2. `apply` kiểm trước mọi thay đổi, board cũ **không bao giờ** đổi:
   - `tokenIndex` ngoài `0..n-1` → `ArgumentError` (như PlacePiece
     với id/ô không tồn tại);
   - `PickToken` cho token **không còn trong pool** (đã ở hàng đáp
     án) → `StateError`; `ReturnToken` cho token **không ở hàng
     đáp án** → `StateError` (như lưới an toàn `StateError` của
     `Board.place`/`Board.unplace` ở E1 — bug lập trình, không
     phải luồng điều khiển).
3. `ReturnToken`: token rời hàng đáp án và trở lại pool đúng **vị
    trí tương đối theo `order`** (pool suy ra từ `order` trừ
  `answer`, nên vị trí cũ tự khôi phục — cùng nguyên lý TrayOrder
  của E3).
4. `toMap()`: đúng ba khóa `v`, `order`, `answer`; `v` = 1; **không
  có seed** trong map (lưu hoán vị, không lưu seed — như E3).
  `fromMap`: mọi dữ liệu hỏng → `FormatException` (thiếu khóa /
  sai kiểu / `v` khác 1 / `order` không phải hoán vị / `answer`
  trùng hoặc chứa chỉ số ngoài `0..n-1`).

```dart
// lib/engine/word/validator.dart — import dart:math show Random + sentence.dart
enum WordCheckStatus { incomplete, correct, incorrect }

final class WordCheck {
  final WordCheckStatus status;
  final String? matchedAnswer; // khi correct: chuỗi đáp án khớp
  bool get isCorrect;
}

final class AnswerValidator {
  AnswerValidator(Sentence sentence, {List<String> alternates = const []});
  Sentence get sentence;
  List<String> get answers;   // không sửa được, câu gốc đầu, đã khử trùng
  WordCheck check(List<int> order);
  bool accepts(List<int> order);
  bool get canScramble;
  List<int> scramble(Random random, {int maxAttempts = 64});
}
```
