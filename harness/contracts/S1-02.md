## 3. Quyết định SA-DB-1 — Bảng progress: PK (image_id, mode), best_time nullable int giây (Opus chốt)

```dart
// lib/data/app_database.dart
class Progress extends Table {
  TextColumn get imageId => text().named('image_id')();
  TextColumn get mode => text()();
  DateTimeColumn get solvedAt => dateTime().named('solved_at')();
  IntColumn get bestTime => integer().named('best_time').nullable()();

  @override
  Set<Column> get primaryKey => {imageId, mode};
}
```

- Tên bảng vật lý: `progress`; tên cột vật lý:
  `image_id`, `mode`, `solved_at`, `best_time` (khớp
  đúng chữ §S1-02).
- `best_time`: **nullable**, đơn vị **giây** (int) —
  null nghĩa là lượt giải không tính giờ / chưa có
  thời gian. Không dùng mili-giây, không dùng Duration
  trong DB.
- `solved_at`: `DateTime` do drift lưu dạng epoch int
  (mặc định của drift, `store_date_time_values_as_text`
  = false). Hệ quả đã kiểm chứng tại máy: giá trị đọc
  lại giữ đúng **mốc thời gian** nhưng có thể là giờ
  địa phương thay vì UTC, và phần lẻ dưới giây bị cắt
  (lưu theo giây). Test so `solved_at` bằng
  `millisecondsSinceEpoch` với thời gian tròn giây
  (UNIT-DB-01/03/04 ghim theo cách so này).

## 5. Quyết định SA-DB-2 + SA-DB-4 — Mode + API DAO + luật upsert (Opus chốt)

File `lib/data/progress_dao.dart`:

```dart
import 'package:drift/drift.dart';

import 'app_database.dart';

part 'progress_dao.g.dart';

/// Giá trị mode lưu trong bảng progress (SA-DB-2):
/// hằng chuỗi trong file DAO, không dùng enum —
/// cổng E5 đếm theo mode ở tầng gọi, DB chỉ lưu trữ.
abstract final class ProgressModes {
  static const String jigsaw = 'jigsaw';
  static const String word = 'word';
}

@DriftAccessor(tables: [Progress, Settings])
class ProgressDao extends DatabaseAccessor<AppDatabase>
    with _$ProgressDaoMixin {
  ProgressDao(super.db);

  /// Đánh dấu một hình đã giải ở một mode (upsert
  /// SA-DB-4): chưa có dòng → chèn mới; đã có dòng →
  /// solved_at GIỮ LẦN ĐẦU, best_time = min(cũ, mới)
  /// theo luật null ở §5.1.
  Future<void> markSolved(
    String imageId,
    String mode, {
    required DateTime solvedAt,
    int? timeSeconds,
  });

  /// Hình này đã giải ở mode này chưa.
  Future<bool> isSolved(String imageId, String mode);

  /// Mọi image_id đã giải ở [mode], sắp xếp tăng dần
  /// theo image_id (tất định cho tầng gọi + test).
  Future<List<String>> solvedIds(String mode);

  /// Đọc một khóa settings; null khi chưa có khóa.
  Future<String?> getSetting(String key);

  /// Ghi một khóa settings; ghi đè khi khóa đã có.
  Future<void> setSetting(String key, String value);
}
```

`AppDatabase` khai `daos: [ProgressDao]` trong
`@DriftDatabase`, nên DAO truy cập qua
`db.progressDao`.

### 5.1. Luật upsert của markSolved (SA-DB-4, ghi nguyên + luật null suy ra từ SA-DB-1)

- Chưa có dòng `(imageId, mode)`: chèn dòng mới với
  `solved_at = solvedAt`, `best_time = timeSeconds`
  (có thể null).
- Đã có dòng: `solved_at` **giữ nguyên lần đầu**
  (tham số `solvedAt` của lần gọi sau bị bỏ qua);
  `best_time` cập nhật theo luật min có null:
  - cũ null, mới có giá trị → lấy giá trị mới;
  - cũ có giá trị, mới null → giữ cũ;
  - cả hai có giá trị → `min(cũ, mới)`;
  - cả hai null → null.
- Hai mode của cùng một `image_id` là **hai dòng độc
  lập** (hệ quả của PK kép SA-DB-1): markSolved ở mode
  này không đụng dòng của mode kia.

Luật null ở trên là cách đọc duy nhất nhất quán với
"best_time = min" + "best_time nullable" của
SA-DB-1/SA-DB-4 (min không định nghĩa trên null nên
phải có luật riêng) — ghi rõ là điểm suy ra, chờ Opus
xác nhận khi soát; UNIT-DB-05/06/07 ghim đúng luật này.

### 5.2. Định nghĩa suy ra khác (chờ Opus xác nhận)

- `solvedIds` sắp xếp **tăng dần theo image_id**: chốt
  SA-DB-4 không nêu thứ tự; thứ tự tất định cần cho
  test ghim và cho tầng gọi so sánh — chọn thứ tự từ
  điển tăng dần (UNIT-DB-09 ghim).
- Truy cập settings nằm trong `ProgressDao` (DAO duy
  nhất của S1-02, accessor khai cả hai bảng). Tách
  DAO riêng cho settings là việc của bước sau nếu
  cần — S1-02 giữ một DAO theo đúng phạm vi chốt
  "bảng + DAO get/set" ở comment `7228829524` mục B.3.

## 6. Quyết định SA-DB-5 — Mở DB: drift_flutter ở production, NativeDatabase file ở test (Opus chốt)

```dart
// lib/data/app_database.dart
@DriftDatabase(tables: [Progress, Settings], daos: [ProgressDao])
class AppDatabase extends _$AppDatabase {
  /// Mở DB bằng một executor có sẵn — test dùng
  /// NativeDatabase trên file tạm qua constructor này.
  AppDatabase(super.e);

  /// Production: mở qua drift_flutter —
  /// driftDatabase(name: 'game_puzzle') cho file
  /// game_puzzle.sqlite trong thư mục documents của app.
  AppDatabase.production()
      : super(driftDatabase(name: 'game_puzzle'));

  @override
  int get schemaVersion => 1;
}
```

- Tên file production: **`game_puzzle.sqlite`** — hệ
  quả trực tiếp của `driftDatabase(name: 'game_puzzle')`
  trong drift_flutter 0.3.1 (đã đọc source package:

- Test DAO **không** dùng `AppDatabase.production()`
  và **không** dùng in-memory: mọi test UNIT-DB mở
  `AppDatabase(NativeDatabase(File(...)))` trên file

  cùng file (đúng chữ §S1-02 "qua hai lần mở").
